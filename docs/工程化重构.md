# 导航模块与测试说明

2026-09-21 将原来集中的 send_goal.py 拆分为 navigation 包；2026-09-22 修正 Gazebo 省略四元数 w 分量的解析。当前验证结论见 [测试报告](测试报告.md)。

## 一次导航

CLI 读取 `x y yaw`（yaw 为度）和配置，创建 `Navigator`。节点预热后等待 Action Server，发送目标，等待接受和结果。确认终态后等待 0.5 秒，再依次读取 Gazebo 真值与 TF，计算三组误差并保存 `NavigationResult`。

`Pose2D`、误差函数、配置与结果对象不依赖 ROS。`initial_pose.ground_truth` 保留旧导入入口，供基线 verify.py 使用；返回 yaw 为弧度，导航报告统一转换为度。

## 超时与取消

等待服务器、目标应答、导航结果分别有超时。耗时与截止时间使用 monotonic，消息头仍使用 ROS 仿真时间。

目标应答超时后先有限等待迟到 handle，仍未收到则按发送时生成的 UUID 请求取消。不会使用 cancel-all。取消请求被接受与确认 CANCELED 是两件事；没有收到终态时，报告保留错误，不能认定机器人已经停止。

超时 outcome 不会因为随后取消成功而改写成成功。Action 成功但采样失败时，CLI 返回非零；CLI 退出 0 只代表执行与采集完整，Goal→TF 阈值由 pytest 验收。

## 三层测试

- 纯函数：位置/角度边界、配置、Gazebo 文本与子进程超时、JSON、缺失采样。
- 模拟通信：使用真实 ROS 消息类型，模拟 Future/goal handle，验证状态和异常分支，不运行 Nav2。
- 集成：独立 Action Server 的 DDS 超时取消，以及实际 TF/Gazebo/传感器、缺失服务器和显式目标导航。

真实导航改变机器人位置，fixture 只清理节点/context，不复位机器人。TF 与 Gazebo 顺序采样，world/map 对齐仅限当前基线，不能用于严格动态同步精度结论。

历史原件在本地保留，公开精选副本见 [证据索引](../results/README.md)；2026-09-21 默认结果为 35 passed / 4 skipped。当前 36 passed / 4 skipped 新增的是一个真值解析回归测试，不是新增真实故障注入。
