# 环境操作说明

当前 baseline 用于 WSL2 Ubuntu 24.04、ROS2 Jazzy、Gazebo 与默认 TurtleBot3 Burger 世界/地图。需要已有 ROS 软件包、Cyclone DDS、Python pytest/PyYAML、用户级 systemd 及 WSLg 图形环境。仓库不打包系统依赖，也没有跨机器复现结论。

以下命令在 Ubuntu 中、克隆后的仓库根目录执行：

```bash
source env.sh
bash run.sh
```

保持终端打开，等待 `Baseline ready`。启动链会停止已有 p2-sim/p2-nav/p2-rviz 服务并重建仿真、定位；不要同时运行另一套 TurtleBot3/Nav2 启动流程。

另开终端进入仓库：

```bash
source env.sh
bash check.sh
python3 verify.py
python3 send_goal.py -1.3 -0.5 0
```

默认目标适用于刚启动的出生位置。导航改变机器人位置，测试 fixture 不复位。CLI 默认写入独立的 results/navigation-*.json；--output 会覆盖指定文件。check.sh 检查生命周期管理器，verify.py 检查数据链。CLI 成功退出不等于精度断言通过，Goal→TF 阈值由 pytest 检查。

停止：启动终端 Ctrl+C，或另开终端运行 `bash stop.sh`。状态和日志：

```bash
systemctl --user status p2-sim p2-nav p2-rviz --no-pager
journalctl --user -u p2-nav -n 50 --no-pager
```

run.sh 将退出日志保存到 logs/；基线会更新 evidence/ 内的运行输出。历史证据需要另行备份，公开副本位于 results/public-*/，不会被这些命令自动覆盖。

## 录制新的 rosbag

先启动并确认数据链；在独立终端录制，再在另一个终端执行导航：

```bash
source env.sh
BAG_PATH="results/navigation-bag-$(date +%Y%m%dT%H%M%S)"
ros2 bag record -s mcap -o "$BAG_PATH" --use-sim-time \
  --qos-profile-overrides-path config/rosbag_qos.yaml \
  --topics /scan /odom /tf /tf_static /cmd_vel /clock /plan /amcl_pose
# Ctrl+C 正常关闭录制后：
ros2 bag info "$BAG_PATH"
```

这是复录命令，不代表新增执行证据。原始 bag 默认忽略，不随 git add 上传。

## 当前配置的运行前提

env.sh 固定加载 /opt/ros/jazzy/setup.bash，设置 ROS_DOMAIN_ID=0、rmw_cyclonedds_cpp 和 WSLg 显示变量。nav.launch.py 使用 /opt/ros/jazzy 下的默认地图；运行前应检查相应包已安装。启动采用分进程 Nav2、时钟转发和用户级服务守护。已有环境故障记录保留本地，不能据此声称上游问题已根治。

make_params.py 会覆盖配置，正常运行无需执行。soak.py/audit.py 是手工诊断工具，其存在不代表已经完成长期稳定性验证。重新启动会重置仿真，不能用来证明真实机器人或故障恢复能力。
